# sapintegrationsuite_api_proxy (Resource)

An API proxy is the API that consumers call: it has its own URL, applies policies such as
authentication, quotas and mediation, and forwards requests to a backend, usually through an
API provider. This resource imports a proxy from its bundle ZIP, the format the API portal
exports, so proxies can be versioned in Git and promoted between tenants.

**Status:** experimental. Needs `enable_experimental = true` in the provider block. The upload
follows SAP's API Management Client SDK 3.0.6 (`POST Transport.svc/APIProxies` with the ZIP),
and the Business Accelerator Hub lists the transport API as official; reading and deleting use
`Management.svc/APIProxies`. The lifecycle has not yet passed its acceptance test on a tenant,
and the schema may change before it is promoted to supported.

## Prerequisites

- `enable_experimental = true`.
- The `api_management` block in the provider configuration, with the role
  `APIPortal.Administrator`.
- The proxy bundle ZIP, containing `APIProxy/<name>.xml` for the proxy named in `name`.
- The API providers the bundle's target endpoint references, for example from
  [`sapintegrationsuite_api_provider`](api_provider.md). SAP rejects the import otherwise.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Checks that the bundle describes the proxy in `name`, uploads it, and waits until the proxy is readable (`timeouts.create`, default 5 minutes). SAP deploys an imported proxy by default. |
| Read | Reads state, status, version, title, description and the API provider. |
| Update | None. |
| Replacement | A new `content_hash` or `content`, or a new `name`, deletes the proxy and imports it again. The proxy is briefly unavailable, and products that include it lose the link. |
| Delete | Deletes the proxy. |

There is no separate deployment resource: SAP documents that an imported proxy is deployed.

## Example Usage

```terraform
# Experimental: needs enable_experimental = true in the provider block.
# Requires provider.api_management to be configured. EXPERIMENTAL.
# The ZIP is an API proxy bundle as the API portal exports it; its
# APIProxy/Orders_v1.xml descriptor must declare the same name. A new
# content_hash deletes the proxy and imports the new bundle.
resource "sapintegrationsuite_api_proxy" "orders" {
  name         = "Orders_v1"
  content      = "${path.module}/proxies/Orders_v1.zip"
  content_hash = filesha256("${path.module}/proxies/Orders_v1.zip")
}

# Products link proxies by name.
resource "sapintegrationsuite_api_product" "orders" {
  name            = "Orders"
  title           = "Orders"
  api_proxy_names = [sapintegrationsuite_api_proxy.orders.name]
}
```

## Schema

### Required

- `content` (String) Path to the API proxy bundle ZIP, for example "${path.module}/proxies/orders.zip". After terraform import, the first apply only records the path; the provider assumes the file matches the proxy on the tenant.
- `content_hash` (String) SHA-256 hash of the bundle, for example filesha256("${path.module}/proxies/orders.zip"). A different hash replaces the proxy.
- `name` (String) The proxy's name, as declared in the bundle's APIProxy/<name>.xml descriptor. It is the proxy's key; changing it replaces the proxy.

### Optional

- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `description` (String) The proxy's description, from the bundle.
- `id` (String) Always equal to name, SAP's key for this entity (APIProxies('<name>')).
- `is_published` (Boolean) Whether the proxy is part of a published product.
- `provider_name` (String) The API provider the target endpoint uses, or NONE for a target URL.
- `service_code` (String) The API type, for example REST, SOAP or ODATA.
- `state` (String) The proxy's deployment state as SAP reports it, for example DEPLOYED.
- `status_code` (String) The proxy's status code as SAP reports it.
- `title` (String) The proxy's title, from the bundle.
- `version` (String) The proxy's version, from the bundle.

## Import

```shell
# The import ID is the proxy's name. The first apply after an import records
# content and content_hash without uploading; the provider assumes the file
# matches the proxy on the tenant.
terraform import sapintegrationsuite_api_proxy.orders Orders_v1
```

The ID is the proxy's name. The first apply after an import only records `content` and
`content_hash`; the provider assumes the file matches the proxy on the tenant.

## Limitations

- **SAP:** the transport API's specification needs an SAP login; the contract comes from SAP's
  Client SDK. Whether importing a changed bundle over an existing proxy replaces it cleanly is
  not documented, which is why changes replace the proxy.
- **Provider:** policies stay inside the bundle; there are no separate policy resources.
  Revisions, undeploy and redeploy of an existing proxy are not managed.
