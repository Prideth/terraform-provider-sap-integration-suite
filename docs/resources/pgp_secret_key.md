# sapintegrationsuite_pgp_secret_key (Resource)

Adds one PGP secret key to the tenant's secret keyring. The PGP decryptor of an integration flow
decrypts with it, and the PGP signer signs with it. The key and its passphrase are
**write-only**: Terraform sends them once and never stores them in plan or state. SAP decrypts
the key with the passphrase and re-encrypts it with one of its own.

**Status:** unofficial. Needs `enable_unofficial = true`. SAP documents PGP keys only in the
Monitor UI (*Manage Security > PGP Keys*). This resource uses what the tenant `$metadata`
declares. A tenant probe verified every request, and the acceptance test added, read, imported
and deleted a key (October 2026). Because the API is undocumented, SAP may change it without
notice.

## Prerequisites

- Terraform 1.11 or later (write-only attributes).
- An OAuth client with `SecurityMaterialEdit`.
- The key as an ASCII-armored block protected by a passphrase, for example from
  `gpg --armor --export-secret-keys <key ID>`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Adds the key to the keyring `secring` (`PUT PgpKeyringSecretResources('secring')/$value`), with the passphrase in the request header `Passphrase`. SAP refuses a wrong passphrase, a public key, and a key ID that exists already. |
| Read | Reads the key by its key ID: type, algorithm, length, user ID, expiry and validity state. Terraform cannot see the key material. |
| Update | Only records `secret_key_wo_version` after an import. |
| Replacement | Changing `secret_key_wo_version` deletes the key and adds the one in `secret_key_wo`. Change it whenever the key changes; Terraform cannot detect a change of a write-only value. |
| Delete | Deletes the key (`DELETE PgpKeyEntries('<key ID>')`). SAP deletes its public part with it, if it holds one. |

## Example Usage

```terraform
# Needs enable_unofficial = true in the provider block, and Terraform 1.11
# or later for the write-only attributes.

variable "pgp_secret_key" {
  type        = string
  sensitive   = true
  description = "Output of gpg --armor --export-secret-keys <key ID>."
}

variable "pgp_passphrase" {
  type      = string
  sensitive = true
}

# The tenant's own key, for the PGP decryptor and the PGP signer. Neither
# the key nor the passphrase is stored in plan or state.
resource "sapintegrationsuite_pgp_secret_key" "tenant" {
  secret_key_wo         = var.pgp_secret_key
  passphrase_wo         = var.pgp_passphrase
  secret_key_wo_version = "1" # change it to send a new key
}
```

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `passphrase_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The passphrase that protects secret_key_wo, sent once in a request header. Write-only: never stored. SAP refuses a wrong one.
- `secret_key_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The secret key as an ASCII-armored block ("-----BEGIN PGP PRIVATE KEY BLOCK-----"), protected by passphrase_wo, as gpg --armor --export-secret-keys writes it. Write-only: Terraform sends it once and never stores it in plan or state. SAP re-encrypts the key with a passphrase of its own. Requires Terraform 1.11 or later.
- `secret_key_wo_version` (String) Any value; change it to send a new secret key. Terraform cannot see changes of the write-only key, so this value decides when the key is replaced: the old key is deleted and the new one added.

### Read-Only

- `algorithm` (String) The public key algorithm as SAP names it, for example "RSA (1)".
- `fingerprint` (String) The v4 fingerprint, 40 hex digits, upper case.
- `id` (String) Always equal to key_id.
- `key_id` (String) The key ID, the last 16 hex digits of the fingerprint, upper case: SAP's key of the PGP key. The PGP encryptor and signer steps of an integration flow reference keys by it or by user ID.
- `key_length` (Number) The key length in bits.
- `primary_user_id` (String) The primary user ID of the key, usually "Name <e-mail>".
- `type` (String) What SAP holds for the key: "Public", "Secret", or "Secret,Public" when its public key was imported as well.
- `valid_until` (String) The expiry of the key, RFC 3339; null for a key that does not expire.
- `validity_state` (String) SAP's validity state: "Valid", "Critical" (expires within 14 days) or "Expired". It changes over time, so a refresh can report it as changed.

## Import

```shell
# The ID is the key ID, the last 16 hex digits of the fingerprint.
terraform import sapintegrationsuite_pgp_secret_key.tenant 0123456789ABCDEF
```

The ID is the key ID. The first apply after an import only records `secret_key_wo_version`; it
does not send the key again.

## Limitations

- **SAP:** SAP deletes a key's public and secret part together. Do not manage the same key with
  this resource and [`sapintegrationsuite_pgp_public_key`](pgp_public_key.md).
- **Provider:** the key ID is known only after the apply, because the key is write-only and not
  part of the plan.
- **Provider:** Cloud runtime only. The keyrings of an Edge Integration Cell were not tested.
