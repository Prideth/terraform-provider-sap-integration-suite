# sapintegrationsuite_key_pair (Resource)

Asks SAP to generate a key pair with a self-signed certificate in the tenant keystore, for
example for client certificate authentication or message signing. The private key is generated
and kept by SAP; this resource has no attribute for it, and the provider never requests it. For
RSA and DSA keys, the public key is also available in OpenSSH format, which covers SSH key
authentication.

**Status:** partial. Generation is documented field by field. SAP documents no update, and only
some of the generation parameters are returned on read. `certificate_signing_request` is
unofficial: it is read only with `enable_unofficial = true`, because the request is known only
from the tenant `$metadata`.

## Prerequisites

- An OAuth client with `SecurityMaterialEdit`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Generates the key pair under `alias`. The alias must not exist. |
| Read | Refreshes key type, key size and validity, and the OpenSSH public key for RSA and DSA. Subject fields and generation parameters are kept from the configuration; empty subject fields are filled from the subject DN SAP returns. With `enable_unofficial = true`, also reads the certificate signing request. Once a CA-signed chain was uploaded, the validity stays as generated (see below). |
| Update | None. |
| Replacement | Changing any attribute generates a **new** key pair, with a new private key. Everything that trusts the old public key, such as a partner's truststore or an SSH server, has to be updated. Read replacement plans for this resource carefully. |
| Delete | Removes exactly this alias from the keystore. |

## Certificate signing request and chain

With `enable_unofficial = true`, `certificate_signing_request` holds a PEM certificate signing
request (PKCS#10) for the key pair, read from `KeystoreEntries('<hexalias>')/SigningRequest/$value`.
Have it signed by a certificate authority and upload the signed certificate with its issuers
through [`sapintegrationsuite_key_pair_certificate_chain`](key_pair_certificate_chain.md). The
CSR stays the same as long as the key pair exists, and becomes unknown in a plan that replaces the
key pair, so a configuration that signs it signs the new key pair's CSR in the same apply.
Without `enable_unofficial`, the attribute is null.

After a chain upload SAP reports the signed certificate's validity for the key pair.
`valid_not_before` and `valid_not_after` keep the values the key pair was generated with, so that
the upload never plans a replacement; the signed certificate's validity is in the chain
resource's `certificates`.

## Example Usage

```terraform
# SAP generates the private key internally; it is never downloadable
# through this API and this resource has no field for it. Every attribute
# that defines the generated key material is RequiresReplace, since SAP
# documents no operation to update a generated key pair in place.
resource "sapintegrationsuite_key_pair" "client_auth" {
  alias        = "client-auth-key"
  key_type     = "RSA"
  key_size     = 2048
  common_name  = "client.example.com"
  country      = "DE"
  organization = "Example GmbH"
}

# An RSA or DSA key pair's public key can be exported in OpenSSH format
# without a separate resource - SAP documents no independent "SSH Key"
# object.
output "client_auth_ssh_public_key" {
  value = sapintegrationsuite_key_pair.client_auth.public_key_openssh
}

# An Elliptic Curve key pair, selected by named curve instead of key_size.
resource "sapintegrationsuite_key_pair" "ec_signing" {
  alias                   = "ec-signing-key"
  key_type                = "EC"
  key_algorithm_parameter = "secp256r1"
  signature_algorithm     = "SHA-256/ECDSA"
  common_name             = "signing.example.com"
  country                 = "DE"
}

# With enable_unofficial = true the key pair also offers a certificate
# signing request; see sapintegrationsuite_key_pair_certificate_chain.
output "client_auth_csr" {
  value = sapintegrationsuite_key_pair.client_auth.certificate_signing_request
}
```

## Schema

### Required

- `alias` (String) The keystore entry alias to create. Must not already exist on the tenant.
- `common_name` (String) Common name (CN) of the certificate's subject distinguished name.
- `country` (String) Country or region (C) of the subject distinguished name. SAP documents this as "two characters required."

### Optional

- `email` (String) E-mail (E) of the subject distinguished name.
- `key_algorithm_parameter` (String) The standard name of an Elliptic Curve domain parameter (for example "secp256r1", "NIST P-256"), used only for key_type "EC" instead of key_size. See docs/guides/security-content.md for the complete confirmed list of accepted values.
- `key_size` (Number) Key size in bits. Must be specified for key_type RSA or DSA. For key_type EC, either key_size (112-571) or key_algorithm_parameter must be specified. SAP's default is 4096 when left unset for RSA/DSA.
- `key_type` (String) One of "RSA" (default), "DSA", "EC" — confirmed as SAP's complete, fixed enum for this field.
- `locality` (String) Locality (L) of the subject distinguished name.
- `organization` (String) Organization (O) of the subject distinguished name.
- `organization_unit` (String) Organizational unit (OU) of the subject distinguished name.
- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.
- `signature_algorithm` (String) The signing algorithm, from a fixed enum that depends on key_type (RSA: SHA-512/RSA (SAP's default), SHA-256/RSA, SHA-384/RSA, SHA-224/RSA, SHA-1/RSA; DSA: SHA-256/DSA, SHA-224/DSA, SHA-1/DSA; EC: SHA-512/ECDSA, SHA-256/ECDSA, SHA-1/ECDSA). Left unset, SAP applies its own default; this provider cannot confirm this value is returned by a subsequent read, so it is not Computed — it is trusted from your configuration once generation succeeds, the same as every other write-only-in-practice generation parameter below. After an import it is unknown; setting it then only records the value.
- `state` (String) State or province (ST) of the subject distinguished name.
- `valid_not_after` (String) Upper boundary of the certificate's validity period, RFC 3339. Left unset, SAP defaults to the current time plus three years.
- `valid_not_before` (String) Lower boundary of the certificate's validity period, RFC 3339 (for example "2026-01-01T00:00:00Z"). Left unset, SAP defaults to the current time.

### Read-Only

- `certificate_signing_request` (String) A PEM certificate signing request (PKCS#10) for this key pair, to have its certificate signed by a certificate authority; the signed chain goes into sapintegrationsuite_key_pair_certificate_chain. Read only with enable_unofficial = true, otherwise null: SAP documents the CSR as a capability of the Key Pair API, but the request (KeystoreEntries('<hexalias>')/SigningRequest/$value) is known only from the tenant $metadata. SAP may sign the request anew, for example after a chain upload; the stored text is kept while subject and public key stay the same, so it changes only when the key pair is replaced, and is unknown in a plan that replaces it.
- `id` (String) Always equal to alias.
- `public_key_openssh` (String) The public key in OpenSSH format ("ssh-rsa AAAA..."), read via SAP's confirmed KeystoreEntries('<hexalias>')/Sshkey/$value export. Only populated for key_type RSA or DSA — SAP documents EC as unsupported for this export; left null for an EC key pair rather than surfacing an error, since not every practitioner generating an EC key pair needs an SSH representation of it.

## Import

```shell
terraform import sapintegrationsuite_key_pair.client_auth client-auth-key
```

The ID is the alias. Key type, size, validity and the subject fields (from the subject DN SAP
returns) are recovered. `signature_algorithm` and `key_algorithm_parameter` are not read; after
an import, setting them in the configuration only records them and does not generate a new key
pair. Any other attribute that differs from what SAP reports forces a replacement, which
generates a new key pair, so check that the first plan after an import replaces nothing.

## Limitations

- **SAP:** no update of a generated key pair. The OpenSSH export does not support EC keys.
- **Provider:** `signature_algorithm` and `key_algorithm_parameter` are not compared with what
  SAP holds, so a change made outside Terraform is not detected. Keys are only generated by SAP; importing an existing private key into the
  keystore is not supported, because the key would have to pass through Terraform.
