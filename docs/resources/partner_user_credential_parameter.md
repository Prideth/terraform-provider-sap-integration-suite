# sapintegrationsuite_partner_user_credential_parameter (Resource)

A user credential parameter stores a user name and password for one partner ID (Pid).
Integration flows use it through the security artifact alias
`pd:<partner_id>:<parameter_id>:UserCredential` that SAP generates, so each partner can have its
own credential for the same flow. The password is write-only: Terraform sends it but never
stores it, and SAP never returns it.

**Status:** supported. Backed by `UserCredentialParameters` of the Partner Directory API.

## Prerequisites

- An OAuth client with the role `AuthGroup_TenantPartnerDirectoryConfigurator`.
- A partner ID (Pid) chosen by you. It does not have to exist: SAP creates a Pid the first time
  an entry references it, and there is no resource for partners themselves.
- Terraform 1.11 or later for the write-only `password_wo`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Stops if the credential exists (SAP's create overwrites), then creates it. |
| Read | Reads the user name. The password is never read. |
| Update | A changed `user` or `password_wo_version` updates the credential in place with `POST`, the update method SAP documents for this entity. Flows keep a valid credential throughout. |
| Replacement | Changing `partner_id`, `parameter_id` or `runtime_location_id` creates a new credential, and flows need the new alias. |
| Delete | Deletes this credential only. |

**Rotating the password.** Put the new password into `password_wo` and change
`password_wo_version`; Terraform cannot see a change of the write-only value itself.

## Example Usage

```terraform
variable "receiver_communication_password" {
  type      = string
  sensitive = true
}

resource "sapintegrationsuite_partner_user_credential_parameter" "receiver" {
  partner_id   = "Receiver_1"
  parameter_id = "USER"
  user         = "commuser1"

  # password_wo is write-only: Terraform never stores it in plan or state.
  # Bump password_wo_version whenever the password itself changes so
  # Terraform detects the rotation (this replaces the resource, since no
  # in-place password update is confirmed for this SAP entity).
  password_wo         = var.receiver_communication_password
  password_wo_version = "1"
}
```

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `parameter_id` (String) The credential parameter's technical ID, unique within its partner.
- `partner_id` (String) The Partner ID (Pid) this credential is scoped to. Does not need to already exist: SAP creates it implicitly on the first entity that references it.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The communication password. Write-only: Terraform never stores this value in plan or state, and it is never read back from SAP. It is sent on create and on every update, since SAP's update replaces user and password together. Requires Terraform CLI 1.11 or later.
- `password_wo_version` (String) An arbitrary value (for example a counter or timestamp) that you change whenever password_wo changes. Terraform cannot see the write-only password, so changing this value is what triggers the in-place update that sends the new password.
- `user` (String) The communication username. Changing it updates the credential in place.

### Optional

- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.

### Read-Only

- `id` (String) Composite identifier in the form "<partner_id>/<parameter_id>".

## Import

```shell
# Import recovers partner_id, parameter_id, and user, but never the
# password: apply a matching configuration right afterward, supplying
# password_wo and a password_wo_version. That first apply plans as a
# replacement even though nothing server-side has actually changed - an
# inherent limitation of importing a write-only-secret resource.
terraform import sapintegrationsuite_partner_user_credential_parameter.receiver Receiver_1/USER
```

The ID is `<partner_id>/<parameter_id>`. Partner, parameter and user are recovered, never the
password; the first apply after an import sends the configured password.

## Limitations

- **SAP:** passwords are never returned, so a password changed elsewhere is not detected. SAP
  does not allow this entity in a batch with other Partner Directory entities; the provider
  always sends it on its own.
- **Provider:** needs Terraform 1.11 or later. Edge Integration Cell targeting through `runtime_location_id` is not supported and has not
  been tested; leave it unset.
