# sapintegrationsuite_script_collection (Resource)

Manages a script collection: Groovy and JavaScript files that several integration flows share
instead of each carrying its own copy. Flows reference the collection by ID; it has to be
deployed before the flows that use it.

**Status:** supported. Backed by `ScriptCollectionDesigntimeArtifacts` of the Integration
Content API. SAP documents creating, reading and deleting script collections. The in-place
content update and `save_as_version` work on a tenant but are not documented, so they need
`enable_unofficial = true`.

## Prerequisites

- An integration package, usually [`sapintegrationsuite_integration_package`](integration_package.md).
- The collection as a ZIP file, as the UI downloads it.
- An OAuth client with `WorkspacePackagesEdit`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Uploads the ZIP. `save_as_version` on create needs `enable_unofficial`. |
| Read | Reads name and version. `content` and `content_hash` keep the values of the last apply. |
| Update | **Needs `enable_unofficial`.** A new `content_hash` or `name` sends the content with `PUT`; a changed `save_as_version` saves a new version. Without the switch, the plan fails with an error that names the operation. |
| Replacement | Changing `script_collection_id` or `package_id` creates a new collection. |
| Delete | Deletes the design-time artifact. |

SAP rejects uploads whose `Bundle-SymbolicName` differs from the ID the collection was created
with. Unlike for flows and message mappings, the provider uploads script collections
unchanged: keep `Bundle-SymbolicName` in the ZIP equal to `script_collection_id`.

## Example Usage

```terraform
resource "sapintegrationsuite_script_collection" "shared" {
  package_id           = sapintegrationsuite_integration_package.utilities.id
  script_collection_id = "shared-scripts"
  name                 = "Shared Scripts"

  content      = "${path.module}/script-collections/shared-scripts.zip"
  content_hash = filesha256("${path.module}/script-collections/shared-scripts.zip")
}
```

## Schema

### Required

- `name` (String) The script collection's display name.
- `package_id` (String) ID of the integration package this script collection belongs to.
- `script_collection_id` (String) The script collection's technical ID. Immutable: changing it replaces the script collection. SAP documents this ID as unique across the entire tenant, not just the package.

### Optional

- `content` (String) Path to the local content file for the script collection project, for example "${path.module}/script-collections/shared-scripts.zip". Required to manage the collection's content; left as-is on import until a matching configuration is applied, since SAP does not return a local file path for an existing design-time artifact.
- `content_hash` (String) SHA-256 hash of the content file, for example filesha256("${path.module}/script-collections/shared-scripts.zip"). Terraform only re-uploads the file when this hash changes.
- `save_as_version` (String) Version to save the uploaded script collection under, for example "1.0.3", using SAP's SaveAsVersion function import. Without it, SAP keeps its own version number and uploads update the current draft. The content is saved as a new version only when this value changes, so bump it together with the content for each release; version then reports what SAP recorded.

### Read-Only

- `id` (String) Composite identifier in the form "<package_id>/<script_collection_id>".
- `version` (String) The design-time version SAP assigned to the most recent upload.

## Import

```shell
terraform import sapintegrationsuite_script_collection.shared UTILITIES/shared-scripts
```

The ID is `<package_id>/<script_collection_id>`. SAP returns no file, so setting `content` in
the configuration makes the first apply upload it, which needs `enable_unofficial`. Leave
`content` and `content_hash` out to adopt a collection with documented operations only.

## Limitations

- **SAP:** no documented update and no documented `SaveAsVersion` for script collections. The
  ID must be unique across the whole tenant, not only within the package.
- **Provider:** files up to 32 MiB from local disk; the bundle ID in the ZIP is not aligned.
