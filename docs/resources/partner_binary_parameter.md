# sapintegrationsuite_partner_binary_parameter (Resource)

A binary parameter stores a file for one partner ID (Pid): a schema, a mapping, a certificate
or other content that integration flows read at runtime, for example in the XML Validator or
XSLT Mapping step. The file is uploaded from local disk. Partner Directory data is stored
unencrypted: never store private keys or secrets here.

**Status:** supported. Backed by `BinaryParameters` of the Partner Directory API.

## Prerequisites

- An OAuth client with the role `AuthGroup_TenantPartnerDirectoryConfigurator`.
- A partner ID (Pid) chosen by you. It does not have to exist: SAP creates a Pid the first time
  an entry references it, and there is no resource for partners themselves.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Uploads the file under `partner_id` and `parameter_id` with `content_type`. |
| Read | Reads the content type. The stored file is not compared, so content changed outside Terraform is not detected; `content_hash` keeps the value of the last apply. |
| Update | A new `content_hash` or `content_type` uploads the file again in place. |
| Replacement | Changing `partner_id`, `parameter_id` or `runtime_location_id` creates a new parameter. |
| Delete | Deletes this parameter only. |

## Example Usage

```terraform
resource "sapintegrationsuite_partner_binary_parameter" "order_schema" {
  partner_id   = "PartnerZ"
  parameter_id = "OrderSchema"

  content_type = "xsd"
  content      = "${path.module}/partner-directory/order-schema.xsd"
  content_hash = filesha256("${path.module}/partner-directory/order-schema.xsd")
}
```

## Schema

### Required

- `content` (String) Path to the local content file, for example "${path.module}/partner-directory/order-schema.xsd".
- `content_hash` (String) SHA-256 hash of the content file, for example filesha256("${path.module}/partner-directory/order-schema.xsd"). Terraform only re-uploads the file when this hash changes.
- `content_type` (String) The content's MIME-like type. SAP documents values including xml, xsl, xsd, json, text, zip, gz, zlib, and crt, and also accepts encoding-suffixed values such as "xml;encoding=UTF-8"; this attribute is not restricted to a fixed list so a value SAP documents but this provider does not yet know about is never rejected client-side.
- `parameter_id` (String) The binary parameter's technical ID, unique within its partner.
- `partner_id` (String) The Partner ID (Pid) this parameter is scoped to. Does not need to already exist: SAP creates it implicitly on the first entity that references it.

### Optional

- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.

### Read-Only

- `id` (String) Composite identifier in the form "<partner_id>/<parameter_id>".

## Import

```shell
terraform import sapintegrationsuite_partner_binary_parameter.order_schema PartnerZ/OrderSchema
```

The ID is `<partner_id>/<parameter_id>`. The file path and hash cannot be recovered; the
first apply after an import uploads the configured file once.

## Limitations

- **SAP:** values up to 1,572,864 bytes (the `MaxLength` in the tenant `$metadata`; older SAP
  pages still say 260 KB). Larger XML content can be stored zipped with `content_type = "zip"`,
  which the XML Validator and XSLT Mapping steps unzip.
- **Provider:** the size is checked before upload. Edge Integration Cell targeting through `runtime_location_id` is not supported and has not
  been tested; leave it unset.
