# sapintegrationsuite_pgp_public_key (Resource)

Adds one PGP public key to the tenant's public keyring. The PGP encryptor of an integration flow
encrypts for it, and the PGP decryptor verifies signatures with it. Flows name the key by its key
ID or user ID. Typically it is a partner's key.

**Status:** unofficial. Needs `enable_unofficial = true`. SAP documents PGP keys only in the
Monitor UI (*Manage Security > PGP Keys*). This resource uses what the tenant `$metadata`
declares. A tenant probe verified every request, and the acceptance test added, read, imported
and deleted a key (October 2026). Because the API is undocumented, SAP may change it without
notice.

## Prerequisites

- An OAuth client with `SecurityMaterialEdit`.
- The key as an ASCII-armored block, for example from `gpg --armor --export <key ID>`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Adds the key to the keyring `pubring` (`PUT PgpKeyringPublicResources('pubring')/$value`). SAP answers per key; when a key with the same key ID exists already, SAP does not add it, and the create fails. Import that key instead. |
| Read | Reads the key by its key ID (`PgpKeyEntries('<key ID>')`): type, algorithm, length, user ID, expiry and validity state. |
| Update | Only records another formatting of the same key, or the text of an imported key; nothing is sent. |
| Replacement | A different key, compared by fingerprint, not by text. |
| Delete | Deletes the key (`DELETE PgpKeyEntries('<key ID>')`). If SAP also holds the secret key, it would delete both, so the key stays and Terraform shows a warning. |

The plan shows `key_id` and `fingerprint` of a new key: the provider computes them from
`public_key` (RFC 4880). `public_key` must hold exactly one primary key, with its sub keys.

## Example Usage

```terraform
# Needs enable_unofficial = true in the provider block.

# A partner's public key, for the PGP encryptor of an integration flow.
# Export it with: gpg --armor --export <key ID>
resource "sapintegrationsuite_pgp_public_key" "partner" {
  public_key = file("${path.module}/keys/partner-public.asc")
}

# Integration flows reference the key by its key ID or user ID.
output "partner_key_id" {
  value = sapintegrationsuite_pgp_public_key.partner.key_id
}
```

## Schema

### Required

- `public_key` (String) The public key as an ASCII-armored block ("-----BEGIN PGP PUBLIC KEY BLOCK-----"), with exactly one primary key and its sub keys, as gpg --armor --export writes it. Not sensitive: public keys are public. A different key replaces the resource; the same key in other formatting does not.

### Read-Only

- `algorithm` (String) The public key algorithm as SAP names it, for example "RSA (1)".
- `fingerprint` (String) The v4 fingerprint, 40 hex digits, upper case.
- `id` (String) Always equal to key_id.
- `key_id` (String) The key ID, the last 16 hex digits of the fingerprint, upper case: SAP's key of the PGP key. The PGP encryptor and signer steps of an integration flow reference keys by it or by user ID.
- `key_length` (Number) The key length in bits.
- `primary_user_id` (String) The primary user ID of the key, usually "Name <e-mail>".
- `type` (String) What SAP holds for the key: "Public", "Secret", or "Secret,Public" when its public key was imported as well.
- `valid_until` (String) The expiry of the key, RFC 3339; null for a key that does not expire.
- `validity_state` (String) SAP's validity state: "Valid", "Critical" (expires within 14 days) or "Expired". It changes over time, so a refresh can report it as changed.

## Import

```shell
# The ID is the key ID, the last 16 hex digits of the fingerprint.
terraform import sapintegrationsuite_pgp_public_key.partner 0123456789ABCDEF
```

The ID is the key ID. SAP does not return the key itself, so `public_key` stays empty until the
next apply. With the same key in the configuration, the provider recognizes it by its
fingerprint and only records the text: nothing is replaced.

## Limitations

- **SAP:** the tenant has one public keyring. Keys of other owners in it are not touched.
- **Provider:** version 4 keys only, the kind gpg and most tools create. Version 5 and 6 keys
  compute their fingerprints differently and are refused in the plan.
- **Provider:** Cloud runtime only. The keyrings of an Edge Integration Cell were not tested.
- **Provider:** `validity_state` changes over time (*Valid*, *Critical* within 14 days of the
  expiry, *Expired*); a refresh reports the change.
