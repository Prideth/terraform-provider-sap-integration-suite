# sapintegrationsuite_message_mapping_deployment (Resource)

Deploys one version of a message mapping to the Cloud Integration runtime. The design-time artifact
is managed by [`sapintegrationsuite_message_mapping`](message_mapping.md); this resource decides which version runs. SAP never deploys a message mapping together with an integration flow that uses it, so a flow that references the mapping needs this resource as well.

**Status:** supported. Backed by `DeployMessageMappingDesigntimeArtifact` and `IntegrationRuntimeArtifacts` of the
Integration Content API.

## Prerequisites

- The message mapping on the tenant, usually from [`sapintegrationsuite_message_mapping`](message_mapping.md).
- An OAuth client with `WorkspaceArtifactsDeploy` and `MonitoringDataRead`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Deploys `mapping_version` and polls the runtime status until SAP reports `STARTED` or `ERROR`, or `timeouts.create` (default 10 minutes) elapses. |
| Read | Reads the runtime artifact. `mapping_version` and `status` reflect what SAP runs now, so a redeploy outside Terraform shows as drift. An artifact that was undeployed outside Terraform drops out of state, and the next apply deploys it again. |
| Update | A new `mapping_version` or changed `redeploy_triggers` redeploys in place. |
| Replacement | Changing `mapping_id`, `package_id` or `runtime_location_id` undeploys and deploys anew. |
| Delete | Sends the undeploy request (bounded by `timeouts.delete`, default 10 minutes); SAP removes the runtime artifact asynchronously. |

If SAP accepted the deploy but the message mapping does not reach `STARTED` in time, or ends in
`ERROR`, the resource stays in state with SAP's last status and error text, and Terraform
marks it tainted. The next apply deploys again. On a tenant, message and value mapping
deployments sometimes stayed `STARTING` for several minutes; raise `timeouts.create` if that
happens on yours.

Uploading new content does not change the message mapping's version. Pass the artifact's
`content_hash` to `redeploy_triggers`, or raise the version, so that new content reaches the
runtime.

## Example Usage

```terraform
resource "sapintegrationsuite_message_mapping_deployment" "customer" {
  package_id      = sapintegrationsuite_integration_package.utilities.id
  mapping_id      = sapintegrationsuite_message_mapping.customer.mapping_id
  mapping_version = sapintegrationsuite_message_mapping.customer.version

  # New content keeps the version, so redeploy whenever the uploaded file changes.
  redeploy_triggers = {
    content = sapintegrationsuite_message_mapping.customer.content_hash
  }

  timeouts {
    create = "10m"
    update = "10m"
    delete = "5m"
  }
}
```

## Schema

### Required

- `mapping_id` (String) ID of the message mapping to deploy.
- `mapping_version` (String) The design-time version to deploy, typically sapintegrationsuite_message_mapping.<name>.version. Changing it redeploys the message mapping. After refresh this also reflects whatever version SAP reports as actually deployed, so a redeploy performed outside Terraform (or a failed/stale deployment) shows up as drift on the next plan.
- `package_id` (String) ID of the integration package the message mapping belongs to.

### Optional

- `redeploy_triggers` (Map of String) Arbitrary values that redeploy the message mapping in place whenever they change, for example its content_hash. Uploading new content does not change the message mapping's version (tenant test, September 2026), so without this or a new mapping_version the runtime keeps the previously deployed content.
- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) Composite identifier in the form "<package_id>/<mapping_id>".
- `status` (String) The runtime status SAP reports for this deployment (for example STARTED or ERROR).

## Import

```shell
terraform import sapintegrationsuite_message_mapping_deployment.customer UTILITIES/customer-mapping
```

The ID is `<package_id>/<mapping_id>`. The deployed version and status are read from the
runtime. `redeploy_triggers` is not known to SAP, so a configuration that sets it redeploys once
on the first apply.

## Limitations

- **SAP:** deployment is asynchronous; SAP reports one deployment per artifact ID.
- **Provider:** Edge Integration Cell targeting through `runtime_location_id` is not supported
  and has not been tested; leave it unset.
