# sapintegrationsuite_custom_tag_configuration (Resource)

Custom tags are the tenant-wide attributes, such as line of business or data owner, that
package owners classify integration packages with. The tenant has exactly one configuration,
so this resource is a singleton: declare it once per tenant, in one configuration only.

**Status:** partial. SAP documents reading and writing the configuration, but no way to delete
or clear it.

## Prerequisites

- An OAuth client with `WebToolingSettingsProductProfiles.savetenantconfiguration`, which SAP
  places in the `PI_Administrator` role collection.
- Agreement on which Terraform configuration owns the tenant's tags. Two configurations that
  both declare this resource overwrite each other.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Writes the complete tag list with SAP's `Overwrite=true` operation. Tags that exist on the tenant but not in `tags` are removed. |
| Read | Reads every tag and its permitted values. A change made in the UI shows as drift. |
| Update | Writes the complete list again with `Overwrite=true`. |
| Replacement | None; the configuration has the fixed key `CustomTags`. |
| Delete | **Fails with an error.** SAP documents no delete or clear operation. To stop managing the tags without changing them, run `terraform state rm`. |

Order carries no meaning: `tags` and each tag's permitted values are sets, so reordering them in
configuration plans no change.

## Example Usage

```terraform
# SAP documents exactly one Custom Tag Configuration per tenant, addressed
# by the fixed key "CustomTags" - this resource is a tenant-wide singleton.
# Every apply sends the complete desired tag list; there is no per-tag
# add/remove operation.
resource "sapintegrationsuite_custom_tag_configuration" "governance" {
  tags = [
    {
      name      = "Owner"
      mandatory = true
    },
    {
      name      = "BusinessUnit"
      mandatory = true

      permitted_values = [
        "Network",
        "Sales",
        "Water",
        "Transport",
      ]
    },
    {
      name      = "Criticality"
      mandatory = false

      permitted_values = [
        "Low",
        "Medium",
        "High",
      ]
    },
  ]
}
```

## Schema

### Required

- `tags` (Attributes Set) The complete desired set of custom tags. Order carries no meaning (SAP's documentation never states it does), so this is a set, not a list: reordering tags in configuration never plans a change. (see [below for nested schema](#nestedatt--tags))

### Read-Only

- `id` (String) Always "CustomTags" — SAP's confirmed fixed identifier for the tenant's one custom tag configuration.

<a id="nestedatt--tags"></a>
### Nested Schema for `tags`

Required:

- `mandatory` (Boolean) Whether an integration package owner must set this tag. SAP's documented examples always set this explicitly (never omit it), so this provider requires it explicitly too rather than assuming an unconfirmed default.
- `name` (String) The tag's name, for example "Owner". Must be unique within this resource.

Optional:

- `permitted_values` (Set of String) An optional closed list of values this tag accepts. Order carries no meaning, hence a set, which also means an exact duplicate value is not representable — SAP's documentation does not confirm whether duplicates are meaningful or accepted, so this provider does not allow configuring one. Leave unset for a free-text tag.

## Import

```shell
terraform import sapintegrationsuite_custom_tag_configuration.governance CustomTags
```

The ID is always `CustomTags`. Importing is the safe way to adopt a tenant that already has
tags: the first plan shows exactly which tags the configuration would add or remove.

## Limitations

- **SAP:** no delete or clear operation. SAP does not state explicitly that `Overwrite=true`
  removes unlisted tags, though the name and the full-list payload say so. Whether tag names
  must be unique and whether permitted values are case-sensitive is not documented; the
  provider enforces unique names itself.
- **Provider:** `terraform destroy` of a configuration that contains this resource fails until
  it is removed from state.
