# sapintegrationsuite_value_mapping_entry (Resource)

A value mapping translates values between systems: for an agency pair (source agency and
identifier, target agency and identifier) it holds source and target value pairs, for example
the country `DE` of an ERP system and `276` of a CRM system. This resource adds one such pair to
an agency pair the value mapping already has, so that the values can be maintained in Terraform
while the value mapping itself comes from
[`sapintegrationsuite_value_mapping`](value_mapping.md) or from SAP's UI.

**Status:** partial. SAP's Integration Content API specification documents the request that adds
an entry, and the resource passed its acceptance test on a tenant, but SAP has no request that
deletes a single entry: destroying the resource leaves the entry in the value mapping. Changing
an entry in place needs `enable_unofficial = true`, because it uses a parameter only the
service's `$metadata` declares.

## Prerequisites

- `enable_unofficial = true` in the provider block to change entries in place.
- A value mapping whose content has the agency pair. SAP adds entries only to existing agency
  pairs and cannot create a pair through the API: define the pair, with at least one entry, in
  the value mapping's content.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Checks that the agency pair exists and that the pair of values is new, then adds it (`UpsertValMaps`). SAP gives the entry an ID and turns the value mapping's version into `Draft`. A pair of values that exists already fails the apply with the import ID to use. |
| Read | Reads the entry by its ID from the agency pair, and whether SAP uses it by default for its source value. An entry that is gone is removed from the state. |
| Update | `source_value` and `target_value` change in place (`UpsertValMaps` with `ValMapId`). Needs `enable_unofficial = true`; without it the plan fails. |
| Replacement | Changing the value mapping or the agency pair creates a new entry and leaves the old one in place. |
| Delete | **Leaves the entry in the value mapping**, with a warning in the plan: SAP has no request that deletes a single entry, and `DeleteValMaps` would remove the whole agency pair, which the API cannot create again. Delete the entry in SAP's UI, or replace the value mapping's content. |

Writes to the same value mapping run one after another, even when Terraform applies several
entries in parallel.

## Default entries

A source value can have more than one target value. SAP then uses one of them by default, and it
makes the newest one the default. `is_default` shows which entry that is.

## Example Usage

```terraform
# The agency pair must exist in the value mapping's content; SAP cannot create
# a pair through the API. Destroying the resource leaves the entry in place.
resource "sapintegrationsuite_value_mapping_entry" "germany" {
  value_mapping_id  = sapintegrationsuite_value_mapping.countries.mapping_id
  source_agency     = "ERP"
  source_identifier = "Country"
  target_agency     = "CRM"
  target_identifier = "CountryCode"
  source_value      = "DE"
  target_value      = "276"
}

# A changed entry reaches the runtime only with a new deployment.
resource "sapintegrationsuite_value_mapping_deployment" "countries" {
  package_id      = sapintegrationsuite_value_mapping.countries.package_id
  mapping_id      = sapintegrationsuite_value_mapping.countries.mapping_id
  mapping_version = sapintegrationsuite_value_mapping.countries.version
  redeploy_triggers = {
    germany = "${sapintegrationsuite_value_mapping_entry.germany.source_value}=${sapintegrationsuite_value_mapping_entry.germany.target_value}"
  }
}
```

## Schema

### Required

- `source_agency` (String) Source agency of the agency pair, as in the value mapping's content. Changing it creates a new entry and leaves the old one in place.
- `source_identifier` (String) Source identifier (schema) of the agency pair. Changing it creates a new entry and leaves the old one in place.
- `source_value` (String) The source value. Changing it changes the entry in place, which needs enable_unofficial = true: the request (UpsertValMaps with ValMapId) is known only from the $metadata.
- `target_agency` (String) Target agency of the agency pair. Changing it creates a new entry and leaves the old one in place.
- `target_identifier` (String) Target identifier (schema) of the agency pair. Changing it creates a new entry and leaves the old one in place.
- `target_value` (String) The target value. Changing it changes the entry in place, which needs enable_unofficial = true: the request (UpsertValMaps with ValMapId) is known only from the $metadata.
- `value_mapping_id` (String) ID of the value mapping, for example sapintegrationsuite_value_mapping.<name>.mapping_id. Changing it creates a new entry and leaves the old one in place.

### Read-Only

- `entry_id` (String) The ID SAP gives the entry (a GUID; the group ID in the value mapping's content).
- `id` (String) <value_mapping_id>/<source_agency>/<source_identifier>/<target_agency>/<target_identifier>/<entry_id>, the form the import takes.
- `is_default` (Boolean) Whether SAP uses this entry by default for its source value, which matters when the source value has more than one target value. SAP makes the newest such entry the default.

## Import

```shell
# <value_mapping_id>/<source_agency>/<source_identifier>/<target_agency>/<target_identifier>/<entry_id>;
# the entry ID is listed by the sapintegrationsuite_value_mapping_entries data source.
terraform import sapintegrationsuite_value_mapping_entry.germany CountryCodes/ERP/Country/CRM/CountryCode/86b4a2f6ff974267993e72f5ce845437
```

Agency names and identifiers that contain a slash cannot be imported.

## Limitations

- **SAP:** no request deletes a single entry. The same source and target value cannot be added
  twice. `IsConfigured` is always sent as `false`: with `true`, SAP marks the agency pair as
  configured and drops the values of the design-time content (tenant check, September 2026).
- **Runtime:** a changed entry takes effect only after the value mapping is deployed again, for
  example through `redeploy_triggers` of
  [`sapintegrationsuite_value_mapping_deployment`](value_mapping_deployment.md).
- **Content uploads:** a new content of `sapintegrationsuite_value_mapping` replaces the value
  mapping and with it every entry added here. Terraform adds them again on the next apply.
