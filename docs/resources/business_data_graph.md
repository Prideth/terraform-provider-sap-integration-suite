# sapintegrationsuite_business_data_graph (Resource)

A business data graph combines the business systems of a landscape, for example SAP S/4HANA and
SAP Sales Cloud, into one connected API. Its configuration says which systems it reads from,
which system leads for which entity, and how keys translate between systems. Client
applications then query the graph; that query traffic is not configuration and is outside
Terraform.

**Status:** supported. SAP documents the create body, reading, the PATCH URL and the status model
of API Composition's Configuration API. It shows no PATCH body and no delete request, so updating
and deleting a graph are unofficial operations that need `enable_unofficial = true`. An acceptance
test created, changed, imported and deleted a graph on a tenant (October 2026).

## Prerequisites

- `enable_unofficial = true` to update or destroy graphs.
- The `api_composition` block in the provider configuration, with a key of an API Composition
  service instance of plan `configuration`. The Cloud Integration and API portal credentials do
  not work for this API.
- Usually a key user login in that block (`username`, `password`, and `origin` for an identity
  provider other than the default): on a test tenant only a user's token with the role collection
  `Graph.KeyUser` was allowed to use the API. See "Logging in as a key user" in the
  [API Composition guide](../guides/api-composition.md).
- The BTP destinations each data source reads from, in the subaccount, with the additional
  property `IntegrationCell.Include = true`. Destinations belong to the SAP/btp provider.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Sends the configuration and waits while SAP reports `PROCESSING`, until `DEPLOYMENT_INITIATED` or `FAILED` (`timeouts.create`, default 20 minutes). |
| Read | Reads the configuration and the processing status, with `status_details` and `log_messages`. |
| Update | **Needs `enable_unofficial`.** Sends the writable properties with `PATCH` and waits again. `exclude` is always sent, so removing it in the configuration also removes it in SAP. |
| Replacement | Changing `business_data_graph_identifier` deletes the graph and creates a new one; needs `enable_unofficial`. Client applications use the identifier in their URL. |
| Delete | **Needs `enable_unofficial`.** Sends `DELETE` to the graph's URL. Without the switch, destroy plans fail. |

A graph that ends in `FAILED` stays in state with SAP's explanation, and Terraform marks it
tainted.

## Example Usage

```terraform
# Updating or destroying a graph needs enable_unofficial = true in the provider block.
# Updating a graph in place and destroying it also need
# enable_unofficial = true, because SAP documents neither request.
# A graph over an S/4HANA system and SAP Sales Cloud. Both destinations
# must exist in the subaccount and carry the additional property
# IntegrationCell.Include = true. Needs provider.api_composition.
resource "sapintegrationsuite_business_data_graph" "sales" {
  business_data_graph_identifier = "sales"

  data_sources = [
    {
      name = "s4"
      # One root destination, several OData services below it.
      services = [
        { destination_name = "s4-root", path = "/odata/sap/API_BUSINESS_PARTNER" },
        { destination_name = "s4-root", path = "/odata/sap/API_PRODUCT_SRV" },
      ]
    },
    {
      name     = "c4c"
      services = [{ destination_name = "c4c-odata" }]
    },
  ]

  locating_policy = {
    # Sales Cloud refers to S/4 products through its own ExternalID field.
    key_mapping = [
      {
        foreign_key = {
          data_source = "c4c"
          entity_name = "sap.c4c.ProductCollection"
          attributes  = ["ExternalID"]
        }
        references = {
          data_source = "s4"
          entity_name = "sap.s4.A_Product"
          attributes  = ["Product"]
        }
      },
    ]

    rules = [
      { name = "sap.s4.*", leading = "s4" },
      { name = "sap.c4c.*", leading = "c4c" },
      { name = "sap.graph.*", leading = "s4", local = ["c4c"] },
      { name = "sap.graph.SalesQuote", leading = "c4c", local = ["s4"] },
    ]
  }

  # Keep Sales Cloud's own entities out of the graph's API.
  exclude = ["sap.c4c.*"]

  # SAP processes the graph asynchronously; the default wait is 20 minutes.
  timeouts {
    create = "30m"
  }
}
```

## Schema

### Required

- `business_data_graph_identifier` (String) Identifier of the graph. Client applications use it in the API Composition URL. Up to 20 lowercase alphanumeric characters separated by hyphens, for example "my-bdg". Changing it replaces the graph.
- `data_sources` (Attributes List) The business systems of the landscape. Each one reads from one or more BTP destinations of the subaccount. (see [below for nested schema](#nestedatt--data_sources))
- `locating_policy` (Attributes) Tells API Composition which data source to read each entity from, and how to translate keys between systems. (see [below for nested schema](#nestedatt--locating_policy))

### Optional

- `description` (String) Description of the graph. Unofficial: the property is known only from the API's $metadata, so setting it needs enable_unofficial = true. When left out, SAP's value is kept and shown.
- `exclude` (List of String) Mirrored entities to remove from the graph's API, by full name, with an optional trailing wildcard, for example ["sap.s4.A_Product", "sap.c4c.*"]. Associations to them disappear as well; custom entities can still use them as a source.
- `graph_model_version` (String) Version of API Composition's unified entity model to build the graph against, for example "1.0.0". SAP fills it when left out.
- `odata_containment` (Boolean) Whether contained entities are reached only through their parent entity (OData containment). SAP enables it by default. Unofficial: SAP describes the setting but names the property (odataContainment) only in the API's $metadata, so setting it needs enable_unofficial = true. When left out, SAP's value is kept and shown.
- `schema_version` (String) Version of the configuration schema. SAP fills it when left out.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `effective_graph_model_version` (String) Model version SAP actually applied.
- `extensions` (List of String) Model extensions of the graph. The Configuration API does not manage extensions, so this is read-only and updates leave them alone.
- `id` (String) Same as business_data_graph_identifier.
- `log_messages` (List of String) Processing log, one JSON document per entry, as SAP returns it.
- `status` (String) Processing status: PROCESSING, DEPLOYMENT_INITIATED or FAILED.
- `status_details` (String) SAP's explanation of the status, mainly for FAILED.

## Import

```shell
terraform import sapintegrationsuite_business_data_graph.sales sales
```

The ID is the graph identifier. The configuration and status are read from SAP.

## Limitations

- **SAP:** extensions cannot be managed through the Configuration API; `extensions` is read-only
  and left alone on update. Cue-scoped key mappings and the OData containment setting have no
  property name in SAP's documentation and cannot be set. SAP does not describe a log entry, so
  each is the JSON SAP returned.
- **Provider:** not yet verified against a live system. The PATCH body and the delete request
  are the provider's inference from SAP's description.
