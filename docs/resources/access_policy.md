# sapintegrationsuite_access_policy (Resource)

An access policy protects artifacts: once a policy's references match an integration flow,
package or other artifact, only users whose role carries the policy's role name can work with
it. The policy itself holds only the role name and a description; the matching rules are
separate [`sapintegrationsuite_access_policy_reference`](access_policy_reference.md) resources.

**Status:** supported. The create, read and delete calls are the ones SAP's own access policy
automation (`SAP/cicd-actions-for-sap-integration-suite`) makes against the Security Content
API. Changing the description uses `PATCH`, which SAP does not document, so it needs
`enable_unofficial = true`.

## Prerequisites

- An OAuth client with `AccessPoliciesEdit` (`AccessPoliciesRead` for the data sources).
- A BTP custom role whose `Values` attribute carries exactly `role_name`, assigned to the people
  who need access. That role belongs to the SAP/btp provider, not to this one.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Creates the policy; SAP assigns the numeric `id`. |
| Read | Reads role name and description by ID. |
| Update | **Needs `enable_unofficial`.** A changed `description` is sent with `PATCH`. Without the switch, the plan fails with an error that names the operation. |
| Replacement | Changing `role_name` creates a new policy. On SAP's side, deleting the old policy also deletes its references. |
| Delete | Deletes the policy and, on SAP's side, its references. |

**Careful:** a policy restricts access for everyone, administrators included. Artifacts that a
new policy matches become inaccessible to anyone without the role (or
`AccessAllAccessPoliciesArtifacts`), including the client that manages them with Terraform.

## Example Usage

```terraform
# The role name must match the Values attribute of a BTP custom role; only
# users holding that role see the artifacts this policy protects.
resource "sapintegrationsuite_access_policy" "utilities" {
  role_name   = "UTILITIES_ARCHITECT"
  description = "Integration flows owned by the utilities architecture team"
}
```

## Schema

### Required

- `role_name` (String) Role name the policy is associated with. Users only get access to the protected artifacts when a BTP custom role carries exactly this string in its Values attribute. Unique per tenant. Changing it replaces the policy, because SAP does not document renaming a policy in place.

### Optional

- `description` (String) Free-text description shown next to the policy in the Access Policies screen.

### Read-Only

- `id` (String) Numeric ID SAP assigns to the policy. It differs between tenants, so use role_name when you need a portable identifier.

## Import

```shell
# The ID is the numeric policy ID SAP assigns. Look it up by role name with the
# sapintegrationsuite_access_policy data source if you do not know it.
terraform import sapintegrationsuite_access_policy.utilities 1901
```

The ID is the numeric policy ID, which differs between tenants. Look it up by role name with the
[`sapintegrationsuite_access_policy`](../data-sources/access_policy.md) data source.

## Limitations

- **SAP:** which runtimes a policy is replicated to (Cloud Integration runtime, Integration Cell,
  Edge Integration Cells) can only be chosen in the UI; the
  [runtime assignments data source](../data-sources/access_policy_runtime_assignments.md) reads
  them.
- **Provider:** renaming a policy in place was not tested, so `role_name` forces replacement.
