# sapintegrationsuite_integration_package_custom_tag (Resource)

Custom tags classify integration packages: a tenant administrator defines tags such as `Owner`,
`BusinessUnit` or `Criticality` once for the whole tenant, and every package then carries a value
for each of them. The tags themselves come from the tenant's custom tag configuration
([`sapintegrationsuite_custom_tag_configuration`](custom_tag_configuration.md)); this resource
sets the values one package has for one tag. That keeps ownership clear when packages are
created by different teams: each team's configuration sets the tags of its own packages, while
the configuration of the tags stays with the tenant administrator.

**Status:** supported. SAP's Integration Content API specification documents reading the tags of
a package and setting one, and a tenant probe settled how SAP stores the values (see below).

## Prerequisites

- The tag exists in the tenant's custom tag configuration, with exactly this name: SAP compares
  names case-sensitively and answers `400 CustomTag '<name>' doesn't exist` for any other. When
  the configuration is managed in the same Terraform configuration, add a `depends_on` on it, so
  that a new tag is defined before a package gets a value for it.
- The package exists. It need not be managed by Terraform: packages copied from SAP's Discover
  catalog or created in the UI can be tagged, too.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Checks that the package lists the tag, then sets the values (`PUT IntegrationPackages('<id>')/$links/CustomTags('<name>')`). A value the tag had before, set in SAP's UI for example, is overwritten. |
| Read | Reads the package's tags and takes this one. A package that is gone, a tag the configuration no longer has, or a tag someone cleared is removed from the state, so the next apply sets the values again (or fails, if the tag is gone from the configuration). |
| Update | `values` change in place with the same request. |
| Replacement | Changing `package_id` or `name` clears the old tag and sets the new one. |
| Delete | Clears the tag (an empty value). Nothing is sent when the package or the tag is already gone. |

Writes to the same package run one after another, even when Terraform applies several tags of it
in parallel.

## How SAP stores the values

SAP keeps all values of a tag in one string separated by `|`. A tenant probe (October 2026)
showed that it trims each value, drops duplicates and keeps the order, storing `["Sales",
"Transport"]` as `Sales | Transport`. So that the stored values always read back as configured,
the provider refuses at plan time what SAP would change: a value containing `|`, a value that
starts or ends with a blank, an empty value and duplicates. Other characters, commas and quotes
included, are stored as they are.

## Example Usage

```terraform
# The tag must exist in the tenant's custom tag configuration. Depending on
# the configuration resource makes Terraform define the tag first.
resource "sapintegrationsuite_integration_package_custom_tag" "owner" {
  package_id = sapintegrationsuite_integration_package.orders.id
  name       = "Owner"
  values     = ["Finance"]

  depends_on = [sapintegrationsuite_custom_tag_configuration.governance]
}

# Several values keep their order.
resource "sapintegrationsuite_integration_package_custom_tag" "business_unit" {
  package_id = sapintegrationsuite_integration_package.orders.id
  name       = "BusinessUnit"
  values     = ["Sales", "Transport"]

  depends_on = [sapintegrationsuite_custom_tag_configuration.governance]
}
```

## Schema

### Required

- `name` (String) Name of the custom tag, exactly as in the tenant's custom tag configuration (SAP compares names case-sensitively). Changing it clears the old tag and sets the new one.
- `package_id` (String) ID of the integration package. Changing it moves the values to another package.
- `values` (List of String) The tag's values, in order. SAP stores them in one string separated by "|", so a value cannot contain "|"; it also trims values and drops duplicates, which the provider therefore refuses at plan time.

### Read-Only

- `id` (String) <package_id>/<name>, the form the import takes.

## Import

```shell
# <package_id>/<name>
terraform import sapintegrationsuite_integration_package_custom_tag.owner OrderProcessing/Owner
```

A tag without a value cannot be imported: there is nothing to manage yet. Declare the resource
instead, and the first apply sets the value.

## Limitations

- **Permitted values and mandatory tags:** the custom tag configuration can restrict a tag to
  permitted values and mark it mandatory. Whether SAP checks permitted values when a value is set
  through the API, and whether it refuses to clear a mandatory tag, was not tested: the test
  tenant had neither. If SAP refuses to clear a mandatory tag, destroying the resource fails;
  `terraform state rm` then stops managing it.
- **Configuration changes:** removing a tag from the custom tag configuration removes its values
  from every package. The resource then disappears from the state on the next refresh, and
  applying it again fails until the tag is configured again.
- **Package updates** through [`sapintegrationsuite_integration_package`](integration_package.md)
  keep the tag values (tenant probe, October 2026).
