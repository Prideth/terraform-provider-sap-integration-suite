# sapintegrationsuite_oauth2_client_credential (Resource)

Holds the client ID, client secret and token URL an adapter uses to fetch an OAuth 2.0 access
token (client credentials grant) before calling a receiver. Integration flows reference it by
its name (`id`). The client secret is write-only: Terraform sends it but never stores it, and
SAP never returns it.

**Status:** partial. Name, description, token URL, client ID, secret, scope, client
authentication, content type, resource and audience are managed. `custom_parameters` is
unofficial and needs `enable_unofficial = true`: SAP does not document how custom parameters
are written, and a tenant check showed that SAP takes them only when the credential is created.

## Prerequisites

- An OAuth client with `CredentialsEdit`.
- Terraform 1.11 or later for `client_secret_wo`.
- The receiver's OAuth client, registered with its authorization server.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Creates and deploys the credential. |
| Read | Reads everything except the secret. |
| Update | Any change redeploys the credential with a full `PUT`. SAP requires the secret on every edit, so the configured `client_secret_wo` is sent each time. `client_authentication`, `scope_content_type`, `resource` and `audience` are optional and computed: when you leave them out, the values SAP holds are sent back. |
| Replacement | Changing `id` creates a new credential. Flows that reference the old name stop working until they are changed. With `custom_parameters` set, every change replaces the credential (see below). |
| Delete | Deletes the credential. |

**Rotating the secret.** Put the new secret into `client_secret_wo` and change
`client_secret_wo_version`. Without a new version, Terraform cannot see that the secret
changed.

## Custom parameters

Some token services expect extra parameters in the token request, for example a `resource`
in the body or a tenant header. `custom_parameters` sends them, each with `send_as_part_of`
`body`, `header` or `url`. SAP treats them differently from every other attribute, as a
tenant check of 2026-10-04 showed:

- SAP takes custom parameters only in the request that creates the credential.
- Every update deletes them, and SAP refuses an update that sends them again.

So with `custom_parameters` set, **every change replaces the credential**, a secret rotation
included: Terraform deletes it and creates it again with the parameters. Integration flows that
use the credential fail for the moment in between, so plan rotations for a quiet time.

Without `custom_parameters`, parameters set in SAP's UI are left alone, but an update deletes
them all the same. The plan then shows the warning *Custom parameters will be deleted* with
their number. Either cancel and put them into `custom_parameters`, or set them again in the
UI after the apply. An import reads the parameters SAP holds, so a configuration that lists the
same ones shows no change.

Parameter values are stored in plan and state. Do not use them for secrets.

## Example Usage

```terraform
variable "backend_client_secret" {
  type      = string
  sensitive = true
}

resource "sapintegrationsuite_oauth2_client_credential" "backend" {
  id                = "BACKEND_OAUTH"
  token_service_url = "https://auth.example.com/oauth/token"
  client_id         = "integration-client"
  scope             = "read write"

  # client_secret_wo is write-only: Terraform never stores it in plan or
  # state. SAP requires re-entering the client secret on every edit, so this
  # provider resends it on every apply that touches this resource, not only
  # when client_secret_wo_version changes.
  client_secret_wo         = var.backend_client_secret
  client_secret_wo_version = "1"
}

# A token service that needs extra parameters. custom_parameters needs
# enable_unofficial = true; SAP takes the parameters only when the
# credential is created, so every change of this resource replaces it.
resource "sapintegrationsuite_oauth2_client_credential" "graph" {
  id                = "GRAPH_OAUTH"
  token_service_url = "https://login.example.com/oauth2/v2.0/token"
  client_id         = "integration-client"

  custom_parameters = [
    { key = "resource", value = "https://graph.example.com", send_as_part_of = "body" },
  ]

  client_secret_wo         = var.backend_client_secret
  client_secret_wo_version = "1"
}
```

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `client_id` (String) The OAuth2 client ID registered with the token service.
- `client_secret_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The OAuth2 client secret. Write-only: Terraform never stores this value in plan or state, and it is never read back from SAP. Required on every apply that creates or redeploys this resource, since SAP documents that editing an OAuth2 Client Credentials artifact requires re-entering the client secret every time.
- `client_secret_wo_version` (String) An arbitrary value (for example a counter or timestamp) that a practitioner changes to signal that client_secret_wo's value has changed and the credential should be rotated. Changing it redeploys the credential in place (SAP's documented "Edit and deploy" action) rather than replacing the resource.
- `id` (String) The credential artifact's name, also called its alias when used in an adapter. This is also this resource's OData key. Immutable: SAP does not document renaming a security material artifact, only deleting and recreating it.
- `token_service_url` (String) URL of the OAuth2 authorization server that issues the access token.

### Optional

- `audience` (String) Audience identifier sent to the token service, for services that require one. Passed through unchanged. Omitting the attribute keeps whatever value SAP currently holds; it cannot be cleared from Terraform.
- `client_authentication` (String) How the client ID and secret are sent to the token service, as SAP stores it in ClientAuthentication. The UI offers "Send as Body Parameter" (default) and "Send as Request Header"; the API constants for these are not documented. Passed through unchanged. Omitting the attribute keeps whatever value SAP currently holds; it cannot be cleared from Terraform.
- `custom_parameters` (Attributes Set) Custom parameters of the token request, each sent in the body, as a header or in the URL. Unofficial: needs enable_unofficial = true, because the parameters are known only from the tenant $metadata. SAP takes them only when the credential is created and deletes them with every update, so with custom_parameters set, every change of this resource, a secret rotation included, replaces the credential: it is deleted and created again, and flows that use it fail in between. Leave the attribute out to leave parameters set in SAP's UI alone; the plan of an update then warns that SAP deletes them. Values are stored in plan and state; do not put secrets into them. (see [below for nested schema](#nestedatt--custom_parameters))
- `description` (String) A free-text description of the credential artifact.
- `resource` (String) Resource identifier sent to the token service, for services that require one. Passed through unchanged. Omitting the attribute keeps whatever value SAP currently holds; it cannot be cleared from Terraform.
- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.
- `scope` (String) OAuth2 scope to request, if the token service requires one.
- `scope_content_type` (String) Content type of the token request, as SAP stores it in ScopeContentType (the UI's "Content Type" field). Passed through unchanged. Omitting the attribute keeps whatever value SAP currently holds; it cannot be cleared from Terraform.

## Import

```shell
terraform import sapintegrationsuite_oauth2_client_credential.backend BACKEND_OAUTH
```

The ID is the credential name. Everything except the secret is recovered; the first apply after
an import redeploys the credential with the configured secret.

## Limitations

- **SAP:** the accepted constants for `client_authentication` and `scope_content_type` are not
  documented; they are passed through as SAP stores them. The grant-type placement shown in the
  UI has no API property.
- **SAP:** an update deletes all custom parameters, and SAP takes them only on create; see
  [Custom parameters](#custom-parameters).
- **Provider:** optional-computed attributes cannot be cleared from Terraform once SAP holds a
  value. OAuth2 authorization code and SAML bearer credentials are separate artifact types and
  not supported; OAuth2 password and SAML bearer credentials have no API.
