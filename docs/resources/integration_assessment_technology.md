# sapintegrationsuite_integration_assessment_technology (Resource)

A technology is an integration product that an assessment can recommend, for example a
third-party middleware. SAP delivers its own technologies; use this resource only for your own,
and look SAP's up with the [technology data source](../data-sources/integration_assessment_technology.md).

**Status:** unofficial. Needs `enable_unofficial = true` in the provider block. SAP documents the
Integration Assessment Entities API and this entity, but the field-level specification on the
Business Accelerator Hub needs an SAP login. The requests follow the service's `$metadata` and
were verified on a tenant in September 2026; SAP may change them without notice.

## Prerequisites

- `enable_unofficial = true` and the `integration_assessment` provider block, with the service key
  of an *Integration Assessment APIs* service instance (plan `default`). The Cloud Integration
  credentials do not work for this API.
- An Integration Assessment subscription in the subaccount.
- A vendor: [`sapintegrationsuite_integration_assessment_vendor`](integration_assessment_vendor.md) or the vendor data source.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Creates the technology of the vendor. |
| Read | Reads the name and the vendor. |
| Update | A new `name` changes the technology in place (PATCH). |
| Replacement | Changing `vendor_id` creates a new technology: changing the vendor in place was not tested. |
| Delete | Deletes the technology. |

## Example Usage

```terraform
# Unofficial: needs enable_unofficial = true and provider.integration_assessment.
# A technology of your own. SAP's technologies already exist on the tenant;
# look them up with the data source of the same name instead.
resource "sapintegrationsuite_integration_assessment_technology" "acme_esb" {
  name      = "ACME Enterprise Service Bus"
  vendor_id = sapintegrationsuite_integration_assessment_vendor.acme.id
}
```

## Limitations

- **SAP:** the service documents limits per tenant: 20,000 applications, 20,000 application
  instances, 50 technologies, 150 technology instances and 10,000 vendors.
- **Provider:** unofficial until the specification is available without a login or verified from
  the Hub download. Ids are UUIDs the service assigns; configurations reference them through
  other resources or the lookup data sources, never as literals.
- **Provider:** the technology's domains, styles and key characteristics (TechnologyDomain,
  TechnologyStyle, TechnologyKeyCharacteristic) are not managed yet; maintain them in the UI.
