# sapintegrationsuite_message_mapping (Resource)

Manages a message mapping artifact: a graphical mapping between two message structures that
several integration flows can reference from a message mapping step. This is the package-level
artifact; a mapping defined inside a flow's own model is part of that flow's ZIP and is managed
with [`sapintegrationsuite_integration_flow`](integration_flow.md).

**Status:** supported. Backed by `MessageMappingDesigntimeArtifacts` of the Integration Content
API. SAP's Integration Content API specification on the Business Accelerator Hub documents
every operation this resource uses: create, read, the in-place update (`PUT`), delete and
`SaveAsVersion`.

## Prerequisites

- An integration package, usually [`sapintegrationsuite_integration_package`](integration_package.md).
- The mapping as a ZIP file (the format the UI downloads), including the source and target
  schemas it references.
- An OAuth client with `WorkspacePackagesEdit`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Uploads the ZIP; with `save_as_version`, saves it under that version. |
| Read | Reads name and version. `content` and `content_hash` keep the values of the last apply. |
| Update | A new `content_hash` or `name` sends the content with `PUT`. A changed `save_as_version` saves a new version. |
| Replacement | Changing `mapping_id` or `package_id` creates a new mapping. |
| Delete | Deletes the design-time artifact. |

Like integration flows, SAP rejects uploads whose `Bundle-SymbolicName` differs from the mapping
ID. The provider uploads a copy with the mapping ID as bundle ID and in `Provide-Capability`,
and warns when it changed anything; your file is not modified.

Deploying the mapping is separate, and SAP never deploys it together with a flow that uses it:
add a [`sapintegrationsuite_message_mapping_deployment`](message_mapping_deployment.md).

## Example Usage

```terraform
resource "sapintegrationsuite_message_mapping" "customer" {
  package_id = sapintegrationsuite_integration_package.utilities.id
  mapping_id = "customer-mapping"
  name       = "Customer Mapping"

  content      = "${path.module}/message-mappings/customer-mapping.zip"
  content_hash = filesha256("${path.module}/message-mappings/customer-mapping.zip")
}
```

## Schema

### Required

- `mapping_id` (String) The message mapping's technical ID. Immutable: changing it replaces the message mapping.
- `name` (String) The message mapping's display name.
- `package_id` (String) ID of the integration package this message mapping belongs to.

### Optional

- `content` (String) Path to the local content file for the message mapping project, for example "${path.module}/message-mappings/customer-mapping.zip". Required to manage the mapping's content; left as-is on import until a matching configuration is applied, since SAP does not return a local file path for an existing design-time artifact. The copy that is uploaded carries mapping_id as Bundle-SymbolicName and in Provide-Capability (the file itself is not changed, and a warning says when this happened): SAP rejects a content update whose bundle ID differs from the mapping ID.
- `content_hash` (String) SHA-256 hash of the content file, for example filesha256("${path.module}/message-mappings/customer-mapping.zip"). Terraform only re-uploads the file when this hash changes.
- `save_as_version` (String) Version to save the uploaded message mapping under, for example "1.0.3", using SAP's SaveAsVersion function import. Without it, SAP keeps its own version number and uploads update the current draft. The content is saved as a new version only when this value changes, so bump it together with the content for each release; version then reports what SAP recorded.

### Read-Only

- `id` (String) Composite identifier in the form "<package_id>/<mapping_id>".
- `version` (String) The design-time version SAP assigned to the most recent upload.

## Import

```shell
terraform import sapintegrationsuite_message_mapping.customer UTILITIES/customer-mapping
```

The ID is `<package_id>/<mapping_id>`. SAP returns no file, so if the configuration sets
`content`, the first apply uploads it as an in-place update. To adopt a mapping without
uploading anything, leave `content` and `content_hash` out until you change the content.

## Limitations

- **SAP:** whether a delete removes every saved version or only the active one is not
  documented.
- **Provider:** files up to 32 MiB from local disk. Content changes made in the UI are not
  detected.
