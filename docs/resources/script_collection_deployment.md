# sapintegrationsuite_script_collection_deployment (Resource)

Deploys one version of a script collection to the Cloud Integration runtime. The design-time artifact
is managed by [`sapintegrationsuite_script_collection`](script_collection.md); this resource decides which version runs. Integration flows that use the collection fail at runtime until it is deployed. Let their deployments depend on this resource.

**Status:** supported. Backed by `DeployScriptCollectionDesigntimeArtifact` and `IntegrationRuntimeArtifacts` of the
Integration Content API.

## Prerequisites

- The script collection on the tenant, usually from [`sapintegrationsuite_script_collection`](script_collection.md).
- An OAuth client with `WorkspaceArtifactsDeploy` and `MonitoringDataRead`.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Deploys `script_collection_version` and polls the runtime status until SAP reports `STARTED` or `ERROR`, or `timeouts.create` (default 10 minutes) elapses. |
| Read | Reads the runtime artifact. `script_collection_version` and `status` reflect what SAP runs now, so a redeploy outside Terraform shows as drift. An artifact that was undeployed outside Terraform drops out of state, and the next apply deploys it again. |
| Update | A new `script_collection_version` or changed `redeploy_triggers` redeploys in place. |
| Replacement | Changing `script_collection_id`, `package_id` or `runtime_location_id` undeploys and deploys anew. |
| Delete | Sends the undeploy request (bounded by `timeouts.delete`, default 10 minutes); SAP removes the runtime artifact asynchronously. |

If SAP accepted the deploy but the script collection does not reach `STARTED` in time, or ends in
`ERROR`, the resource stays in state with SAP's last status and error text, and Terraform
marks it tainted. The next apply deploys again. On a tenant, message and value mapping
deployments sometimes stayed `STARTING` for several minutes; raise `timeouts.create` if that
happens on yours.

Uploading new content does not change the script collection's version. Pass the artifact's
`content_hash` to `redeploy_triggers`, or raise the version, so that new content reaches the
runtime.

## Example Usage

```terraform
resource "sapintegrationsuite_script_collection_deployment" "shared" {
  package_id                = sapintegrationsuite_integration_package.utilities.id
  script_collection_id      = sapintegrationsuite_script_collection.shared.script_collection_id
  script_collection_version = sapintegrationsuite_script_collection.shared.version

  # New content keeps the version, so redeploy whenever the uploaded file changes.
  redeploy_triggers = {
    content = sapintegrationsuite_script_collection.shared.content_hash
  }

  timeouts {
    create = "10m"
    update = "10m"
    delete = "5m"
  }
}
```

## Schema

### Required

- `package_id` (String) ID of the integration package the script collection belongs to.
- `script_collection_id` (String) ID of the script collection to deploy.
- `script_collection_version` (String) The design-time version to deploy, typically sapintegrationsuite_script_collection.<name>.version. Changing it redeploys the script collection. After refresh this also reflects whatever version SAP reports as actually deployed, so a redeploy performed outside Terraform (or a failed/stale deployment) shows up as drift on the next plan.

### Optional

- `redeploy_triggers` (Map of String) Arbitrary values that redeploy the script collection in place whenever they change, for example its content_hash. Uploading new content does not change the script collection's version (tenant test, September 2026), so without this or a new script_collection_version the runtime keeps the previously deployed content.
- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) Composite identifier in the form "<package_id>/<script_collection_id>".
- `status` (String) The runtime status SAP reports for this deployment (for example STARTED or ERROR).

## Import

```shell
terraform import sapintegrationsuite_script_collection_deployment.shared UTILITIES/shared-scripts
```

The ID is `<package_id>/<script_collection_id>`. The deployed version and status are read from the
runtime. `redeploy_triggers` is not known to SAP, so a configuration that sets it redeploys once
on the first apply.

## Limitations

- **SAP:** deployment is asynchronous; SAP reports one deployment per artifact ID.
- **Provider:** Edge Integration Cell targeting through `runtime_location_id` is not supported
  and has not been tested; leave it unset.
