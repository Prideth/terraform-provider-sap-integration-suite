# sapintegrationsuite_certificate (Resource)

Adds a trusted X.509 certificate to the tenant keystore under an alias. Adapters use trusted
certificates to validate the TLS certificates of receivers and to verify signatures. The
certificate is public data and is not marked sensitive; private keys never go into this
resource.

**Status:** supported. Backed by `CertificateResources` and the keystore operations of the
Security Content API.

## Prerequisites

- An OAuth client with `SecurityMaterialEdit` (`MonitoringDataRead` for the data sources).
- The certificate in PEM format, and the fingerprint your partner gave you to compare it with.

## Lifecycle

| Operation | What happens |
|---|---|
| Create | Imports the certificate under `alias`. Fails if the alias exists; import it instead. |
| Read | Reads the certificate SAP holds and compares its SHA-256 fingerprint with `certificate_sha256`. A different certificate on the tenant shows as drift; different line wrapping or line endings of the same certificate do not. |
| Update | A new `certificate` replaces the certificate under the same alias (`update=true`). The fingerprint, subject, issuer and serial number are recomputed from the new PEM at plan time. |
| Replacement | Changing `alias` or `runtime_location_id` creates a new entry. SAP has a rename operation, which this resource does not use. |
| Delete | Removes exactly this alias from the keystore, using SAP's keystore delete operation with a one-entry list. |

**Trust decision.** SAP asks for fingerprint confirmation when a certificate is self-signed or
not trusted. The provider confirms it (`fingerprintVerified=true`), so listing a certificate in
the configuration is the decision to trust it. Compare `certificate_sha256` in the plan with the
fingerprint you expect before applying.

## Example Usage

```terraform
# certificate is public X.509 content, never a secret - it is never marked
# Sensitive. Drift detection compares a canonical SHA-256 fingerprint of
# the certificate's DER bytes, not raw PEM text, so re-wrapped or
# CRLF-converted PEM content never causes a spurious diff.
resource "sapintegrationsuite_certificate" "backend_ca" {
  alias       = "backend-root-ca"
  certificate = file("${path.module}/backend-root-ca.pem")
}

output "backend_ca_fingerprint" {
  value = sapintegrationsuite_certificate.backend_ca.certificate_sha256
}
```

## Schema

### Required

- `alias` (String) The keystore entry's alias. This is the entity's actual identity (SAP's OData key is this alias' hex encoding, computed internally — you never provide it), so it is RequiresReplace: SAP documents a separate, explicit rename operation (PUT KeystoreEntries('<hex>')?renameAlias=<new>) this resource does not use, to keep lifecycle behavior predictable.
- `certificate` (String) The X.509 certificate in PEM format ("-----BEGIN CERTIFICATE-----...-----END CERTIFICATE-----"). Not Sensitive: public certificate content is not confidential. On refresh, if the certificate actually deployed on the tenant is byte-identical in substance to this value (compared via certificate_sha256, not raw text — see that attribute), this provider keeps your own PEM text unchanged in state rather than replacing it with SAP's own re-serialization, so differences in line wrapping or line endings never produce a spurious plan diff. A genuinely different certificate on the tenant does update this value, surfacing real drift.

### Optional

- `runtime_location_id` (String) NOT SUPPORTED YET. Edge Integration Cell targeting has not passed its acceptance test on a tenant with an Edge Integration Cell; leave this unset until it has. If set, requests go to /location/<id>/api/v1 on the same tenant host, the service root SAP Help documents for Edge Integration Cells, and the value is the runtime location ID SAP shows in the monitoring URL after selecting the Edge Integration Cell as runtime ({"edge":{"runtimeLocationId":"myedge"}}). Use it only at your own risk. Changing it replaces the resource.

### Read-Only

- `certificate_sha256` (String) The SHA-256 fingerprint (lowercase hex) of the certificate's DER bytes, computed locally by this provider from the certificate content — not a value SAP's API returns. Used internally to detect genuine certificate changes independent of PEM text formatting; exposed because it is generally more useful for policy checks and cross-referencing than comparing raw PEM text.
- `id` (String) Always equal to alias.
- `issuer_dn` (String) The certificate's issuer distinguished name, parsed locally from the certificate content.
- `serial_number` (String) The certificate's serial number (decimal), parsed locally from the certificate content.
- `subject_dn` (String) The certificate's subject distinguished name, parsed locally from the certificate content (Go's crypto/x509), not a raw SAP-returned field — see docs/guides/security-content.md for why.

## Import

```shell
terraform import sapintegrationsuite_certificate.backend_ca backend-root-ca
```

The ID is the alias. The certificate is read from SAP, so an import recovers everything.

## Limitations

- **SAP:** there is no per-entry delete; the provider uses the documented keystore mass delete
  with exactly the one alias it owns.
- **Provider:** SAP-owned entries (owner `SAP`, for example SAP's root certificates) should not
  be managed. Edge Integration Cell targeting is not supported.
